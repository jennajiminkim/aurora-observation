# v2.7 verification record — Daily Max & Verification Menu

Date: 2026-10-09. This is a **local synthetic browser regression test**. None of these 14/7/65/6/12 pt examples are actual NOAA evidence or the user's own observations.

The regression test loads the actual `index.html`, `styles.css`, and `app.js` in a headless Chromium page; only the external network fetch is mocked because the test environment blocks local page navigation.

## Test cases

1. Same KST date: sequential successful NOAA-shaped responses **14, 7, 65, 6 pt**. Assert `LATEST=6`, `MAX=65`, and `max_source_time` remains the timestamp accompanying **65 pt**. Assert the day still has exactly **one** row.
2. Next KST day: a successful **12 pt** response creates exactly one additional row and preserves the prior day's `MAX=65`; `YESTERDAY=6`, `CHANGE=+6`.
3. Threshold archive: genuine-NOAA-path mock **65 pt** triggers one event. Preview with simulated **85 pt** creates **no new** daily row, maximum, or event.
4. Verification navigation: `VERIFICATION` hides the normal dashboard, retains RAW/STORED/SCREEN values, and runs Card 3 public fixture success/failure/recovery while real reading/event state is unchanged.
5. Legacy storage: upgrading a v2.6-style row whose latest stored value is **42 pt** but which has no MAX field, then fetching **7 pt**, leaves the baseline `MAX=42` and original NOAA timestamp; previous higher peaks are never fabricated.
6. Original public files' byte-level SHA-256 verified unchanged:

## Limits

- This regression test is **not** a live NOAA availability check, deployed Vercel check, or substitute for actual KST two-day evidence.
- Values saved before v2.7 were latest-only. Existing earlier highs on the same day cannot be reconstructed.
- SHA-256 calculation for original public fixture files was performed on local project bytes; the public deployed site's hash button should be rechecked after uploading.
